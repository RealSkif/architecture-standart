| Код | Требования                                                                              | Комментарий  |
|-----|-----------------------------------------------------------------------------------------|--------------|
| F   | Функциональные (Functionality)                                                          |              |
| F1  | Клиент может видеть список депозитов с актуальными ставками на сайте и в интернет-банке | Для сайта — общие ставки, для интернет-банка — персонализированные |
| F2  | Клиент может подать заявку на депозит на сайте, указав ФИО и телефон                    | Заявка поступает в систему кол-центра |
| F3  | Менеджер кол-центра может просмотреть заявку и предложить особые условия                | Возможность ручной обработки заявки |
| F4  | После звонка клиенту необходимо прийти в отделение для идентификации                    | Требование законодательства РФ |
| F5  | В интернет-банке клиент может выбрать счёт, сумму и подать заявку на депозит            | |
| F6  | Подтверждение заявки в интернет-банке через СМС-код                                     | Требует интеграции с СМС-шлюзом |
| F7  | Клиент получает СМС-уведомления о статусе заявки и открытии депозита                    | |
| F8  | Сотрудники бэк-офиса могут работать со ставками в XLS/АБС                               | Требуется поддержка совместного доступа |
| U   | Удобство использования (Usability)                                                      |              |
| U1  | Интерфейс максимально удобен для клиента, соответствует дизайн-системе банка            | Важно для привлечения новых клиентов |
| U2  | Быстрый отклик интерфейса (операции — менее секунды)                                    | Сейчас есть задержки при загрузке справочников |
| U3  | Привычные цвета и брендированные элементы                                               | Требование бизнеса |
| R   | Надёжность (Reliability)                                                                |              |
| R1  | Сервисы должны быть доступны 24/7, SLA — 99,9%                                          | Особенно для интернет-банка и сайта |
| R2  | В случае сбоя в ЦОД возможен перевод на резервный ЦОД                                   | Для интернет-банка реализовано вручную |
| R3  | АБС масштабируется только вертикально                                                   | Ограничение платформы |
| R4  | Все сервисы должны корректно обрабатывать ошибки интеграции                             | |
| P   | Производительность (Performance)                                                        |              |
| P1  | Время отклика интерфейса — не более 1 секунды                                           | Для всех пользовательских операций |
| P2  | Система выдерживает одновременную работу всех клиентов                                  | Горизонтальное масштабирование для интернет-банка и сайта |
| P3  | Не допускается деградация производительности АБС                                        | Новые процессы не должны перегружать БД АБС |
| S   | Поддерживаемость (Supportability)                                                       |              |
| S1  | Использование существующих технологий банка (MS SQL, Oracle, .NET, Java, React)         | Минимизирует риски и ускоряет внедрение |
| S2  | Возможность расширения функционала (API, микросервисы)                                  | В перспективе — переход к микросервисной архитектуре |
| S3  | Документирование всех изменений и интеграций                                            | Для дальнейшего развития системы |
| R+  | + Ограничения (Restrictions)                                                            |              |
| R1  | Передача чувствительных данных только по защищённым каналам (TLS/SSL)                   | Для сайта и интернет-банка |
| R2  | Прямая интеграция интернет-банка с АБС запрещена для новых процессов                    | Требование надёжности и производительности |
| R3  | Ставки по депозитам должны быть доступны только авторизованным сотрудникам              | Требование безопасности |
| R4  | Для обмена с внешними кол-центрами использовать только файловый обмен                   | Нет возможности API/SFTP у партнёра |
| R5  | Использование очередей сообщений — только Kafka (при необходимости)                     | Но текущая версия интернет-банка несовместима с Kafka |
| R6  | Все решения должны быть совместимы с текущей экспертизой IT-команды                     | Важно для поддержки и развития |
