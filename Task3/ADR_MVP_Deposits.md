### <a name="_qmphm5d6rvi3"></a>**Решение**

**Логика принятия решений:**

1. **Архитектурный подход:** Выбрана гибридная архитектура с разделением на фронтенд-системы (сайт, интернет-банк) и бэкенд-системы (АБС, кол-центр). Это позволяет избежать прямой нагрузки на АБС.

2. **Интеграция:** Использование промежуточного слоя (API Gateway) для интеграции между системами, что обеспечивает гибкость и масштабируемость.

3. **Безопасность:** Все внешние взаимодействия защищены TLS/SSL, внутренние - через защищённые каналы.

4. **Технологии:** Использование существующего стека технологий банка для минимизации рисков и ускорения внедрения.

**Основные компоненты:**

- **API Gateway:** Центральная точка интеграции, обеспечивает маршрутизацию запросов и трансформацию данных
- **Сервис ставок:** Отдельный сервис для управления ставками по депозитам
- **Сервис уведомлений:** Централизованная система отправки СМС
- **База данных ставок:** Отдельная БД для хранения актуальных ставок
- **Очередь сообщений:** Для асинхронной обработки заявок

**Диаграммы:** См. файлы `Context_Diagram.drawio` и `Container_Diagram.drawio`

### <a name="_bjrr7veeh80c"></a>**Альтернативы**

**Альтернатива 1: Прямая интеграция интернет-банка с АБС**
- Преимущества: Простота реализации, меньше компонентов
- Недостатки: Нагрузка на АБС, риски производительности, сложность масштабирования

**Альтернатива 2: Микросервисная архитектура с Kafka**
- Преимущества: Высокая масштабируемость, отказоустойчивость
- Недостатки: Сложность внедрения, несовместимость с текущей версией интернет-банка

**Альтернатива 3: Централизованная система управления депозитами**
- Преимущества: Единая точка управления всеми процессами
- Недостатки: Сложность интеграции с существующими системами, высокие риски

**Недостатки, ограничения, риски**

**Недостатки выбранного решения:**
1. Увеличение сложности системы за счёт дополнительных компонентов
2. Необходимость синхронизации данных между системами
3. Зависимость от внешних сервисов (СМС-шлюз)

**Ограничения:**
1. АБС может масштабироваться только вертикально
2. Текущая версия интернет-банка несовместима с Kafka
3. Ограничения по интеграции с внешними кол-центрами

**Риски:**
1. Риск перегрузки АБС при росте нагрузки
2. Риск несогласованности данных между системами
3. Риск недоступности внешних сервисов (СМС-шлюз)
4. Риск сложности поддержки новой архитектуры для IT-команды
